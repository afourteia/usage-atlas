DATA SOURCES

Data sources and limitations

Quota sources

Codex uses its official app-server protocol. Claude runs the built-in /usage command. Kimi uses its official Code usage API, with the CLI handling credential refresh.

Reset times

Bars show the percentage used. Hourly, weekly, model-specific, and monthly windows appear only when reported. An expired countdown waits for a new reading; it never assumes your quota has reset.

Daily token activity

Codex reports account-wide daily activity. Claude shows its CLI's cached activity on this machine, which may include earlier sign-ins in that profile. Kimi does not expose daily token history through its quota endpoint. Tokens do not directly translate to subscription percentages.

Hourly token heatmaps

Heatmaps count timestamped usage records in the official CLIs' local session logs. Each response is counted once, including cached input tokens. Global totals combine the indexed profiles. Shared log directories are counted under their owning profile. Account attribution follows the log directory, so earlier sign-ins in that profile may be included. Zero means no tokens recorded locally, not zero usage on other devices. Dates and hours use UTC.

History retention

Atlas polls every five minutes and keeps 90 days of quota samples on this machine. Failed polls preserve the last reading and mark it stale. History charts use hourly averages.

Network access

This dashboard is for your trusted Tailscale devices. Anyone your tailnet rules allow to reach it can see account emails and usage. Credentials are never sent to the browser.
